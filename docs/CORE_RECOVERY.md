# Сессии, поиск и уведомления — сентябрь 2026

- Повтор операции обновления сессии восстанавливает тот же действующий токен из подтверждённой записи БД. Redis больше не ограничивает восстановление нововыданных токенов сутками. Проверяются пользователь, срок, отзыв и MFA; операция не продлевает срок и не восстанавливает уже использованный следующий токен. Старые записи кэша поддерживаются до истечения их прежнего TTL.
- HTML-каталоги используют тот же поиск по публичным полям и порядок релевантности, что `/v1/listings`. Скрытые признаки, точный адрес и внутренний код не индексируются.
- Если фото невозможно сравнить, его вес исключается. Реальное несовпадение двух обработанных фото учитывается. Название участвует в сравнении и для вручную заполненных объявлений без AI-тегов. Балл — ранжирование, не вероятность владения.
- Worker раз в пять минут повторяет обработку очищенных фото без вектора, затем запускает сопоставление. Уже существующее совпадение тоже уведомляет при первом достижении порога; повторная обработка не создаёт дубликаты уведомлений.
- Web Push включается пользователем в кабинете, на странице «Уведомления». Разрешение запрашивается только по нажатию. На iPhone требуется поддерживаемая версия iOS и приложение, установленное через Safari на экран «Домой».
- VAPID-ключ получается из серверного секрета с отдельным криптографическим назначением; клиент получает только открытый ключ. Дополнительные ключи на VPS не требуются. Смена APP_SECRET требует повторной подписки.
- Подписки зашифрованы; допустимы только HTTPS endpoint известных браузерных служб. Запросы не используют proxy-переменные окружения и не следуют перенаправлениям. Блокированный пользователь, удалённая подписка и прочитанное уведомление исключаются из доставки.
- Попытки хранятся в PostgreSQL, повторяются с задержкой до пяти раз, прекращаются при 404/410. На экран блокировки не выводятся название вещи, адрес, телефон или текст переписки. По нажатию открывается кабинет. Явный выход отключает подписку на текущем устройстве; временный сбой сети не является выходом.

## Приёмка после деплоя

1. В установленной iPhone PWA войти, свернуть/закрыть, сменить сеть и открыть снова: сохранённая сессия доступна.
2. Сравнить поиск одинаковой фразы на сайте и в приложении, включая словоформы и публичные теги.
3. Включить уведомления, закрыть PWA, получить ответ от второго тестового пользователя, открыть уведомление. Затем отключить уведомления и повторить проверку.
4. Проверить применение миграции `0004_push_delivery` и выдачу `/app/push-client.js` и `/app/bureau-push-sw.js` как JavaScript.

Автотесты покрывают потерю ответа/кэша, возврат спустя семь дней, отзыв и истечение сессии, согласованный поиск, восстановление векторов, очередь push, шифрование, отказ от подписки и миграцию. Успешный CI не подтверждает доставку через Apple/Google на физическое устройство.
